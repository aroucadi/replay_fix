## Executive Summary

ReplayFix v1.8.0 scales ReplayFix from a single-agent workstation tool into an **enterprise-grade distributed visual repair cluster and real-time observability center**.

Modern engineering teams encounter complex visual defects reported in production across diverse browsers, devices, and real-user session recordings. ReplayFix v1.8.0 introduces five core architectural pillars to address this:
1. **Production APM Session Replay & Log Ingestion (`replayfix ingest`)**: Directly ingests real-user session recordings (RRWeb event streams, OpenTelemetry spans, Sentry/Datadog crash breadcrumbs), parses DOM mutation trees, user interaction streams, and stack frames, and compiles them into deterministic ReplayFix reproduction manifests (`TaskManifest`).
2. **Distributed Work-Stealing Triage Swarm (`replayfix swarm --workers <N>`)**: Multi-core, high-concurrency worker cluster with work-stealing job orchestration, per-worker isolated scratch worktrees ($\Delta\text{repo}=0$), dynamic ephemeral port allocations (`:0`), and rate-limited Meta Muse model pool concurrency (`ModelPool`).
3. **Live Streaming Replay Dashboard & Telemetry Server (`replayfix dashboard --port <port>`)**: An embedded high-performance async HTTP & RFC 6455 WebSocket / SSE web dashboard streaming real-time browser CDP viewport screen frames, live DOM mutation streams, Turn-by-Turn Meta Muse Spark agent reasoning timelines, and side-by-side pre/post repair diffs to maintainers in real time via single-page `dashboard.html`.
4. **Cross-Browser & Multi-Device Inoculation Matrix (`replayfix inoculate --matrix`)**: Extends permanent test inoculation (`InoculationGenerator`) to synthesize responsive Playwright test matrices covering Desktop Chromium, WebKit, Firefox, and simulated mobile viewports (e.g. iPhone 14, Pixel 7) with DPR coordinate calibration.
5. **RFC 6962 Merkle Receipt Transparency Log & Key Notary (`replayfix notary`)**: An append-only, cryptographic transparency ledger (`transparency_log.json`) chaining all historical triage receipts with Merkle consistency proofs, verifiable offline via CLI and `proof_viewer.html`.

## The 5 Pillars of Release 1.8

### Pillar 1: Production APM & RRWeb Session Replay Ingestion (`replayfix-core::rrweb`, `replayfix ingest`)
- **RRWeb Event Parsing (`RrwebParser`)**: Full ingestion of RRWeb v2 recordings, extracting full DOM snapshots, incremental DOM mutations, mouse clicks, scrolls, and text inputs with high temporal fidelity.
- **Sentry / APM Crash Ingestion (`SentryIngestion`)**: Ingests Sentry crash JSON dumps (local or remote via HTTPS), parses unhandled exceptions, candidate source files from stack frames, and user action breadcrumbs.
- **Automated Manifest Synthesis (`synthesize_manifest_from_telemetry`)**: Combines interaction trajectories and stack frames into validated `TaskManifest` specs with strict path traversal defenses (`TaskManifest::assert_safe_path`).

### Pillar 2: Distributed Work-Stealing Triage Swarm (`replayfix-core::swarm`, `replayfix swarm`)
- **Concurrent Worker Cluster (`SwarmCoordinator`)**: Multi-threaded execution pool supporting configurable concurrency (`--workers <N>`), work-stealing task queues, and dynamic SLA deadlines.
- **Hermetic Ephemeral Sandboxes**: Every worker operates within its own dedicated scratch clone with dual-layer immutability verification, guaranteeing $\Delta\text{repo}=0$ on the host workspace.
- **Dynamic Port Isolation (`EphemeralPort`)**: Automatic allocation of unused TCP ports (`:0`) prevents socket collision across concurrent workers.
- **Swarm Summary Aggregation**: Generates machine-readable `swarm_summary.json` matching `contracts/swarm_task.schema.json`.

### Pillar 3: Live Streaming Observability Dashboard (`replayfix-core::dashboard`, `replayfix dashboard`)
- **Embedded Async/Threaded Server**: High-performance HTTP daemon with pure Rust RFC 6455 WebSocket handshakes and Server-Sent Events (SSE) reasoning token streaming.
- **Zero-Dependency Single-Page UI (`dashboard.html`)**: Complete responsive interface featuring live viewport canvas viewer, Turn-by-Turn deliberation timeline, and real-time DOM diff inspector under a strict Content Security Policy.
- **REST Telemetry APIs**: Exposes `/api/status`, `/api/tasks`, and `/api/receipts` for programmatic fleet monitoring.

### Pillar 4: Cross-Browser & Multi-Device Inoculation Matrix (`replayfix-core::inoculate`, `replayfix inoculate --matrix`)
- **Multi-Engine Matrix Generation**: Synthesizes Playwright test matrices running across Chromium, Firefox, and WebKit engines simultaneously.
- **Responsive Viewport Presets**: Built-in support for `desktop` (1920x1080), `tablet` (820x1180, DPR 2.0), and `mobile-portrait` (390x844, DPR 3.0) configurations.
- **Device Pixel Ratio (DPR) Calibration**: `calibrate_viewport_coords` dynamically scales interaction coordinates between source recording viewport and target test devices.

### Pillar 5: RFC 6962 Merkle Receipt Transparency Log & Key Notary (`replayfix-core::notary`, `replayfix notary`)
- **Append-Only Cryptographic Ledger (`transparency_log.json`)**: Chains historical triage receipts using RFC 6962 Merkle tree hashes (`0x00` leaf prefix, `0x01` interior node prefix).
- **Consistency Proofs (`subproof`, `verify_consistency_proof`)**: Calculates and verifies cryptographic consistency proofs between earlier and later log snapshot sizes, proving tamper-evident ledger append history.
- **Ed25519 Signatures & Key Transparency**: Every snapshot root is digitally signed using RFC 8032 Ed25519, allowing independent offline verification via `replayfix notary verify-log`.
