## 1. Executive Summary

ReplayFix **v0.3.3** is the qualified release gate for the v0.3 minor release series. Following the delivery of ephemeral scratch isolation (`v0.3.0`) and the world-class terminal user experience (`v0.3.1` and `v0.3.2`), v0.3.3 harmonizes the workspace crates, verifies cross-platform execution on Windows 11, resolves batch script probes for Node/npx tools in `doctor`, and confirms strict adherence to the project's engineering principles.

With this release, the baseline for subsequent milestones (beginning with Playwright CDP grounding in `v0.4.0`) is rigorously verified, architecturally clean, and fully covered by automated regression tests.

## 2. Key Changes & Enhancements

### 2.1 Workspace Version Harmonization
- Synchronized `crates/replayfix-core` and `crates/replayfix-cli` to unified version `0.3.3`.
- Updated inter-crate dependency constraints to ensure clean package resolution across local paths and cargo manifests.

### 2.2 Windows Script Probe Resolution in `replayfix doctor`
- **Issue**: On Windows systems, executables invoked without file extensions (such as `npx` or `playwright`) fail when they are wrapped in `.cmd` or `.bat` batch scripts, causing false-negative `[MISSING]` errors even when tools are properly installed.
- **Resolution**: `Platform::create_command` in `crates/replayfix-core/src/platform.rs` now checks for `.cmd` wrappers on Windows for `npx`, `npm`, and `playwright`, correctly invoking them via Windows process spawning.
- **Result**: `replayfix doctor` accurately reports `Playwright 1.64.1` (and all other prerequisites: Git, Node.js, FFmpeg) as `[OK]` and compatible.

### 2.3 Terminal UX & Trust Boundary Verification
- Verified three distinct output modes: `OutputMode::Human` (styled terminal with cards and step badges), `OutputMode::Quiet` (minimal errors-only output), and `OutputMode::Machine` (clean JSON streaming).
- Deterministic color precedence: `--color always` > `--color never` > `NO_COLOR` > `CLICOLOR_FORCE` > `TERM=dumb` > `io::IsTerminal`.
- Validated `--dry-run` operational safety mode, allowing pre-flight validation of inputs, manifests, security boundaries, and candidate patch size without modifying files or running processes.
