# Release Notes — ReplayFix v0.4.1

**Release Date**: 2026-10-27
**Tag**: `v0.4.1`
**Specification**: `specs/040-v0.4-playwright-cdp-grounding` (High-Risk Systems Gate Hardening)

---

## Summary

ReplayFix **v0.4.1** is a high-assurance systems hardening release following an adversarial engineering review of the **v0.4.0** Playwright CDP browser bridge, child process timeout enforcement, protocol correlation, and DOM node resolution lifecycle.

This release eliminates seven confirmed failure modes across synchronous stdio pipe reads, child `stderr` pipe buffer deadlocks, request/response correlation, browser WebSocket disconnection detection, DOM time-of-check/time-of-use (TOCTOU) detachment, duplicate-selector ambiguity bypasses, and idle HTTP socket stalls.

---

## Defects Remediated in v0.4.1

### 1. Non-Blocking Bounded Stdout Pipe Reader & Command Deadlines (`PlaywrightBridge`)
- **Problem (F-01)**: `PlaywrightBridge::send_command` previously performed a synchronous blocking `BufReader::read_line` on the child's `stdout` OS pipe with no timeout and no line-length bound, allowing a wedged Chromium/Node process or an unterminated line to hang the Rust process indefinitely.
- **Fix**: Replaced blocking pipe reads with a dedicated background reader thread (`spawn_stdout_reader`) using `read_bounded_line` (`MAX_STDOUT_LINE_BYTES = 4 MiB`) and `mpsc::Receiver::recv_timeout`. Every command is now strictly bounded (`DEFAULT_BRIDGE_STARTUP_TIMEOUT = 20s`, `DEFAULT_BRIDGE_COMMAND_TIMEOUT = 15s`, `SHUTDOWN_COMMAND_TIMEOUT = 1.5s`), and timeouts immediately poison the bridge and terminate the child process tree.

### 2. Continuous Background `stderr` Drain & Crash Diagnostics (`spawn_stderr_drainer`)
- **Problem (F-02)**: `PlaywrightBridge::start` piped child `stderr` (`Stdio::piped()`) without draining it, creating a classic OS pipe-buffer deadlock whenever Node.js or Chromium emitted >64 KiB to `stderr` and losing diagnostic output when the child crashed.
- **Fix**: Added a background `stderr` drain thread (`spawn_stderr_drainer`) maintaining a bounded 64-line ring buffer (`MAX_STDERR_LINES = 64`), preventing pipe backpressure deadlocks and appending captured `stderr` context to all timeout, EOF, and protocol errors.

### 3. Monotonic Request Correlation (`request_id`) & Poison-on-Desync
- **Problem (F-03)**: Commands and responses had no correlation identifier, allowing late responses from timed-out commands or corrupted out-of-order payloads to desynchronize subsequent requests.
- **Fix**: Every command now carries a monotonically increasing `request_id: u64` echoed by `PLAYWRIGHT_BRIDGE_JS`. Late responses (`resp_id < req_id`) are safely discarded while waiting for `req_id`, and future/mismatched IDs (`resp_id > req_id`) or malformed JSON immediately poison and terminate the bridge.

### 4. Browser WebSocket Disconnection, Target Crash & CDP Operation Timeouts (`PLAYWRIGHT_BRIDGE_JS`)
- **Problem (F-04)**: `PLAYWRIGHT_BRIDGE_JS` did not attach `browser.on('disconnected')`, `page.on('crash')`, or `page.on('close')` listeners, and left `ariaSnapshot()`, `page.evaluate()`, and `browser.close()` without explicit promise deadline guards.
- **Fix**: Added `withTimeout` promise race bounds across all CDP/Playwright calls (`launch: 15s`, `goto: 10s`, `ariaSnapshot: 5.5s`, `evaluate: 5s`, `browser.close: 2s`) and added `ensureActivePage()` checks verifying WebSocket connectivity and target health before and after navigation and clicks.

### 5. DOM Node TOCTOU Verification & Duplicate-Selector Ambiguity Guard (`LocatorResolver` & `CLICK_AND_OBSERVE`)
- **Problem (F-05)**:
  1. `LocatorResolver::resolve` filtered runner-up candidates with `sel != &top_selector`, allowing two distinct `<button>Refresh Cart</button>` elements on the same page to bypass the ambiguity guard and fail later in Playwright strict mode.
  2. When a candidate was not matched in `ariaSnapshot` (`aria_verified == false`) but carried a `data-testid`, `synthesize_selector` still synthesized an ungrounded `page.getByRole(...)` instead of `page.getByTestId(...)`.
  3. Between `PROBE_PAGE` and `CLICK_AND_OBSERVE`, a resolved DOM node could be detached or hidden without an explicit pre-click check.
- **Fix**:
  1. `LocatorResolver::resolve` now rejects any selector that matches `> 1` grounded DOM candidates on the page (`Ambiguous grounding ... matches N distinct DOM elements`).
  2. `LocatorResolver::synthesize_selector_for_grounding` and `execute_browser_gate` only use `getByRole` when `aria_verified == true` and fall back to `getByTestId` otherwise.
  3. `CLICK_AND_OBSERVE` explicitly verifies `locator.count() === 1` and non-zero `locator.boundingBox()` before clicking, surfacing `DOM_NODE_DETACHED` or `AMBIGUOUS_GROUNDING` immediately.

### 6. Idempotent Shutdown & Single-Execution Process-Tree Termination
- **Problem (F-06)**: `PlaywrightBridge::shutdown` was called both explicitly and in `Drop`, risked blocking on `child.wait()`, and could invoke `Platform::terminate_process_tree` multiple times on an already-reaped PID.
- **Fix**: Added `shut_down: bool` and `terminated: bool` guards, bounded `SHUTDOWN` IPC (`1.5s`), single-execution `terminate_process_tree`, and bounded `reap_child_bounded` (`try_wait` polling up to `500ms`).

### 7. Concurrent Per-Connection HTTP Handling in `SandboxServer`
- **Problem (F-07)**: `SandboxServer` handled HTTP connections synchronously on the accept thread with a 2-second read timeout, allowing a single idle speculative TCP connection from Chromium to stall concurrent asset requests and delay `SandboxServer::shutdown()`.
- **Fix**: Spawned short-lived per-connection worker threads with a 250ms loopback read timeout, 500ms write timeout, and a 32 MiB (`MAX_HTTP_FILE_BYTES`) file size guard.
