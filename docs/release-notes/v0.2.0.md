# ReplayFix v0.2.0 — The Mock Healer

**Released:** 2026-10-27 · **Spec:** `specs/020-v0.2-mock-healer-two-gates`

v0.2.0 proves ReplayFix's control flow end to end: a bug must reproduce (RED), a patch must apply, and the **same** behavioral check must then pass (GREEN). Everything runs against a simulated oracle, so this release shows the state machine, the patcher and the receipt format working. It does not verify real browser behavior yet.

## Try it

```bash
cargo build --release
replayfix repro --task-id RF-01 --bug-ref bug/RF-01 --video recordings/RF-01.mp4 --mock-heal
# -> .replayfix/audit_receipt.json (VERIFIED_REPAIRED), exit 0

replayfix repro --task-id RF-01 --bug-ref bug/RF-01 --video recordings/RF-01.mp4 --mock-heal --mock-patch noop
# -> .replayfix/triage_report.json (REPAIR_NOOP_REJECTED), exit 30
```

## What's new

- **Two-gate state machine.** `Init → Gate1Red → Repair → Gate2Green`, with a terminal `Rejected`. Skipping a gate or leaving a terminal state is an error.
- **Contract invariance.** Gate 2 refuses to run if its contract differs from Gate 1's (SHA-256 of canonical JSON).
- **Strict in-memory patcher.** Single-file unified diffs with exact line offsets and context. No fuzzy matching, so a patch that only applies "approximately" is rejected.
- **Anti-no-op guard.** Empty, whitespace-only and net-zero patches are rejected. A patch that doesn't actually fix the defect ends with Gate 2 still RED.
- **Honest receipts.** Success writes `audit_receipt.json`; rejection writes `triage_report.json` and deletes any older receipt in the folder. Every receipt states that the oracle is simulated.
- **New `repro` flags.** `--mock-heal`, `--mock-patch <builtin|noop|FILE>`, `--output-dir <DIR>`.

## Exit codes

| Code | Meaning |
| :--- | :--- |
| 0 | Repair verified |
| 2 | Bad input or usage (unknown task, unreadable or oversized patch file, missing flags) |
| 10 | Gate 1 was not RED, or the contract changed between gates |
| 11 | Security violation (unsafe path in a patch header, `--mock-patch` or `--output-dir`) |
| 30 | Repair rejected (no-op, patch did not apply, Gate 2 not green) |

## Housekeeping

- Removed an orphaned Windows runner script and six unused dependencies.
- The CLI version now comes from the crate metadata.
- Added `scripts/sign-build-outputs.ps1` and a troubleshooting section for Windows Smart App Control blocks (see `docs/windows-code-signing.md`).
- 66 core unit tests and 15 CLI integration tests.

## Upgrading from v0.1.x

No migration needed. Existing `doctor` and `repro` commands work as before; `repro` without `--mock-heal` now prints a clearer status line. Library users who match `CoreError` exhaustively need one extra arm for `CoreError::Patch`.

## Known limitations

- Only task `RF-01` has a built-in scenario.
- The oracle inspects a bundled source snippet. It says nothing about real browser behavior (v0.4).
- Your repository is not read or isolated yet (v0.3).
- Patches that touch test files are not rejected yet, and there is no two-run stability pass (v0.7).
- Receipts are not signed (v0.9).
- On Windows with Smart App Control you may need `scripts/sign-build-outputs.ps1` after building before the CLI tests can run.
