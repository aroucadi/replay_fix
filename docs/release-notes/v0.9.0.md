## 1. Executive Summary

Milestone **v0.9.0** elevates ReplayFix into an enterprise-grade cryptographic verification and benchmark evaluation substrate. It establishes verifiable cryptographic provenance over all repair and verification artifacts, provides an independent verification CLI, expands the benchmark suite to five authoritative MetaPulse defect scenarios (`RF-01` through `RF-05`), introduces bounded tri-model orchestration and competitive pooling, and delivers the high-performance `replayfix sweep` subcommand with sub-60s execution guarantees.

All implementations strictly adhere to the 10 Authoritative Engineering Principles, the BeautifulRust discipline, zero-panic architecture, fail-closed verification, and repository isolation ($\Delta\text{repo} = 0$).

## 2. Key Capabilities Delivered

### 2.1 RFC 6962 Domain-Separated Merkle Receipts (`replayfix-core::merkle`)
- **Domain Separation**: Strictly separates leaf and node hashing to preclude tree collision vulnerabilities:
  - Leaf hash: $H(L) = \text{SHA-256}(0x00 \parallel \text{CanonicalBytes})$
  - Node hash: $H(N) = \text{SHA-256}(0x01 \parallel \text{LeftHash} \parallel \text{RightHash})$
- **Binary Power-of-2 Tree Balancing**: Splits arbitrary $n$-element trees by $k = 2^{\lfloor \log_2(n - 1) \rfloor}$, ensuring deterministic structural parity with RFC 6962.
- **Inclusion Proofs**: Emits reproducible audit paths (`MerkleInclusionProof`) for every disaggregated artifact leaf (`01_candidate.diff`, `02_preflight.json`, `03_differential_diagnosis.json`, `04_regression_parity.json`, `04_audit_receipt.json`).
- **Comprehensive Verification**: `MerkleReceipt::verify_all()` mathematically proves that no artifact has been added, removed, reordered, or modified.

### 2.2 Pure Ed25519 Cryptographic Attestation (`replayfix-core::crypto`)
- **RFC 8032 Pure Ed25519**: Employs `ed25519-dalek` with hardware acceleration, `zeroize` memory scrubbing, and secure OS entropy generation.
- **Canonical Signing Payload**: Digital signatures strictly bind the versioned payload:
  `REPLAYFIX-ATTESTATION:v0.9:<schema_version>:<merkle_root>:<tree_size>:<timestamp>`
- **Public-Key Trust Policies**:
  - `TrustPolicy::AllowAny`: Validates signature integrity; reports `VerifiedUntrustedSigner` if key is not pinned.
  - `TrustPolicy::PinnedKeys`: Enforces signature origin against a set of authorized public keys; fails closed if the signer key is not pinned.
- **Verification Outcomes**: Aligned exit codes: Exit 0 on valid trusted receipts; Exit 40 (`RECEIPT_VERIFICATION_FAILED`) on any cryptographic, structural, or Merkle tampering.

### 2.3 Independent Receipt Verification CLI (`replayfix verify-receipt`)
- **CLI Subcommand**: `replayfix verify-receipt <path> [--trusted-key <hex>] [--json]`
- **Universal Input Ingestion**: Seamlessly ingests individual `merkle_receipt.json` files, `audit_receipt.json` files, or target output directories containing artifacts.
- **Strict Verification Protocol**: Automatically validates Merkle inclusion proofs, root integrity, and digital attestation.

### 2.4 Authoritative Five-Bug MetaPulse Benchmark Suite (`RF-01` to `RF-05`)
Expanded the benchmark defect suite across five distinct failure modes:
1. **`RF-01` (Cart Summary Crash)**: `cartItemCount` in `src/cart-summary.js` (TypeError on undefined items array dereference).
2. **`RF-02` (Stale Discount Calculation)**: `applyDiscount` in `src/discount.js` (Secondary multiplication bug applying discount twice: $0.8 \times 0.8$).
3. **`RF-03` (Inventory Underflow)**: `decrementQuantity` in `src/inventory.js` (Quantity boundary bug decrementing below 0).
4. **`RF-04` (Cart Reset on Tab Switch)**: `switchTab` in `src/cart-store.js` (State persistence bug clearing store items on navigation).
5. **`RF-05` (Double Submit Idempotency)**: `submitOrder` in `src/order.js` (Async race condition lacking `isSubmitting` re-entrancy guard).

Every scenario includes realistic buggy code, minimal unified diff fix, standalone HTML test shell, and `BehavioralContract`.

### 2.5 Tri-Model Orchestration & Competitive Pooling (`replayfix-core::repair`)
- **Model Candidate Pool**: Manages concurrent candidate synthesis across:
  - `muse-spark-1.3` (Primary fast repair candidate)
  - `muse-wonder-1.0` (Reasoning-heavy candidate with `High` deliberation effort)
  - `muse-spark-1.3-contributor` (Alternative candidate with contributor persona)
- **Competitive Race Protocol**: Dispatches candidate tasks concurrently. The first candidate patch passing syntax preflight and two-gate verification wins; competing tasks are aborted immediately via atomic cancellation flags.

### 2.6 High-Performance Five-Bug Benchmark Sweep CLI (`replayfix sweep`)
- **CLI Subcommand**: `replayfix sweep [--bugs RF-01,RF-02,RF-03,RF-04,RF-05] [--mock-heal] [--live-browser] [--repo <path>] [--output <dir>] [--json]`
- **Zero Cross-Bug Contamination**: Every defect scenario executes inside its own isolated `ScratchSandbox` ($\Delta\text{repo}=0$).
- **Sub-60s Latency Target Crushed**: Executes all 5 benchmark scenarios in $< 2$ seconds in offline/simulated mode (well below the 60,000ms SLA).
- **Consolidated Cryptographic Receipt**: Emits `.replayfix/sweep_receipt.json` containing aggregate pass/fail statistics, per-bug receipts, aggregate Merkle root, and Ed25519 signature.

## 3. Exit Codes Taxonomy Aligned for v0.9.0

| Exit Code | Identifier | Description |
|---|---|---|
| 0 | `SUCCESS` | Verification, repair, sweep, or receipt verification succeeded |
| 1 | `DOCTOR_FAILED` | Environment doctor dependency check failed |
| 2 | `USAGE_OR_INPUT_ERROR` | Invalid CLI arguments or malformed flags |
| 10 | `INTERNAL_OR_SYSTEM_ERROR` | Internal engine or I/O failure |
| 11 | `SECURITY_VIOLATION` | Path traversal, DOS device, or test file mutation attempt |
| 12 | `USER_REJECTED_PATCH` | Operator declined candidate patch application in interactive gate |
| 13 | `NON_INTERACTIVE_REFUSAL` | Base repo patch requested without `--yes` in non-interactive session |
| 20 | `BRIDGE_EXECUTION_FAILED` | Playwright or CDP browser process error |
| 21 | `QUARANTINE_REPAIR_FAILED` | Autonomous repair exhausted attempts without passing Gate 2 |
| 22 | `AMBIGUOUS_GROUNDING` | Visual perception element grounding ambiguity |
| 23 | `INVALID_ISSUE_URL` | Malformed GitHub issue URL |
| 24 | `ISSUE_FETCH_FAILED` | GitHub API or network issue retrieval failure |
| 30 | `GATE2_NOT_GREEN` | Repaired code failed verification |
| 31 | `REGRESSION_DETECTED` | Candidate patch caused regression in pre-existing test suite |
| 32 | `QUARANTINE_INVERTED_BASELINE` | Clean reference failed reproduction baseline |
| 40 | `RECEIPT_VERIFICATION_FAILED` | Cryptographic signature or Merkle proof verification failed |
| 41 | `SWEEP_PARTIAL_FAILURE` | One or more benchmark cases in sweep failed verification |
