## Key Hardening & Enhancements

### 1. Adversarial Prompt Injection Defense (`replayfix-core::ingestion`)
- **Delimiter Breakout Prevention**: Untrusted GitHub issue titles, raw bodies, and extracted reproduction steps are automatically sanitized against embedded `<UNTRUSTED_ISSUE_METADATA>` and `</UNTRUSTED_ISSUE_METADATA>` tags prior to context construction. Delimiters are safely entity-escaped, guaranteeing that adversarial issue descriptions cannot escape their security sandbox.
- **Unit Test Coverage**: Added `adversarial_prompt_injection_tags_are_escaped` verifying single delimiter boundary containment under adversarial attack payloads.

### 2. Authenticated GitHub Ingestion & Rate Limit Resilience (`replayfix-core::ingestion`)
- **Bearer Token Support**: `SystemIssueFetcher` now inspects `GH_TOKEN` and `GITHUB_TOKEN` environment variables, automatically supplying `Authorization: Bearer <token>` when querying the GitHub REST API.
- **Leak-Proof Error Handling**: API authentication tokens are never mirrored to logs, console output, or error messages.
- **Structured Error Parsing**: GitHub API error payloads (`{"message": "...", "documentation_url": "..."}`) are parsed directly, returning informative diagnostics for `Bad credentials`, `Not Found`, and `API rate limit exceeded`.

### 3. Terminal Injection Sanitization (`replayfix-cli::approval`)
- **ANSI Escape Neutralization**: The unified diff highlighter (`highlight_diff`) now scans each diff line and replaces embedded raw ANSI control bytes (`\x1b`) with safe printable representations (`^[`). This neutralizes terminal escape sequence injection attacks (cursor manipulation, terminal title hijacking, OSC 8 hyperlinks, line erasing) from untrusted diffs.
- **Interactive EOF Fail-Closed**: Added fail-closed EOF handling for interactive confirmation streams, ensuring immediate rejection with `ManualNegative` audit records when stdin closes unexpectedly.

### 4. Specification Conformance & Exit Code Parity
- **Spec 080 Harmonization**: Reconciled acceptance criteria in `specs/080-v0.8-observability-ingestion/spec.md` with the authoritative exit code mapping in Section 4:
  - Exit 12: `USER_REJECTED_PATCH` (Operator declined patch application)
  - Exit 13: `NON_INTERACTIVE_REFUSAL` (Base repo modification requested non-interactively without `--yes`)
  - Exit 23: `INVALID_ISSUE_URL` (Malformed or unsupported GitHub issue URL)
  - Exit 24: `ISSUE_FETCH_FAILED` (Network or API issue retrieval failure)
