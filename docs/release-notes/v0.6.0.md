## 1. Executive Summary

Release `v0.6.0` delivers **Spec 060 (`060-v0.6-meta-model-bounded-repair`)**, replacing static fixture patches with a **bounded autonomous repair loop** (`replayfix_core::repair`) backed by anti-cheating SHA-256 test freezing, prompt-injection data fencing, Meta Muse model routing with encrypted deliberation continuity (`reasoning.encrypted_content`), strict 5-field JSON Schema output validation, ambiguity-safe source-block patching, preflight `node --input-type=module --check` syntax validation, 2-run Gate 2 stability verification, and integer micro-dollar token accounting.

---

## 2. Key Architectural Deliverables

### 2.1 Anti-Cheating SHA-256 Test Freeze (`TestFreezeGuard`)
- Before any repair attempt begins, `TestFreezeGuard::capture` scans the scratch sandbox and computes SHA-256 digests (`frozen_files`) and an aggregate digest (`aggregate_sha256`) for all test files and runner configurations (`tests/**`, `__tests__/**`, `*.spec.*`, `*.test.*`, `playwright.config.*`, `jest.config.*`, `vitest.config.*`, `tsconfig*.json`, `package.json`).
- `TestFreezeGuard::validate_target_path` normalizes separators and collapses traversal segments (`..`) to block any candidate patch targeting protected paths across case variants (`TESTS\Foo.SPEC.ts`) or path traversal (`src/../../tests/foo.spec.ts`) with `CoreError::SecurityViolation("TEST_MUTATION_PROHIBITED")` (exit code `11`).
- `TestFreezeGuard::verify_integrity` re-scans the sandbox after every disk write to guarantee 100% SHA-256 parity on all frozen files.

### 2.2 Meta Muse Model Routing & Reasoning Effort Bounds (`MuseModelConfig`)
- Supports `muse-spark-1.3` (`effort: "xhigh"`), `muse-wonder-1.0` (`effort: "high"`), `muse-spark-1.3-contributor` (`effort: "xhigh"`), and open-weights fallback `meta-models/muse-spark-open-1026`.
- Explicitly rejects disallowed legacy slug `muse-wonder-full-1.0` (`MODEL_DISALLOWED`) and prohibits `effort: "max"` (`EFFORT_MAX_PROHIBITED`).
- Records both `requested_model`, `serving_model`, and `provider_mode` (`"deterministic-offline-fixture"` vs `"live-meta-api"`) for transparent audit attribution.

### 2.3 Prompt-Injection Isolation & Static 24h Prefix Caching (`PromptBuilder`)
- Places the trusted `STATIC_SYSTEM_PREFIX` first (`prompt_cache_key: "replayfix-v0.6-harness-prefix-v1"`, `prompt_cache_retention: "24h"`).
- Wraps all untrusted repository source code, Gate 1 stack traces, and retry compiler diagnostics inside `<UNTRUSTED_CONTEXT kind="...">...</UNTRUSTED_CONTEXT>` tags, neutralizing any embedded `</UNTRUSTED_CONTEXT>` or `<UNTRUSTED_CONTEXT>` substrings via `PromptBuilder::escape_untrusted`.

### 2.4 Meta Superpower #3 — Encrypted Deliberation Continuity (`RepairRequest`)
- Requests `include: ["reasoning.encrypted_content"]` on every repair invocation.
- On retry attempts (`Attempt 2` and `Attempt 3`), threads `previous_response_id` and `encrypted_content` alongside the bounded compiler or Gate 2 failure diagnostic so the model resumes its prior reasoning chain rather than restarting from scratch.

### 2.5 Strict JSON Schema & Ambiguity-Safe Source-Block Patching (`StructuredRepairPatch` & `BlockPatcher`)
- `StructuredRepairPatch::decode_strict` enforces the 5-field schema (`explanation`, `target_file`, `search_block`, `replace_block`, `touched_symbols`) with `#[serde(deny_unknown_fields)]` and rejects markdown code fences (` ```json `).
- `BlockPatcher::apply` enforces exact single-match uniqueness of `search_block` within `target_file` (returning `PATCH_TARGET_NOT_FOUND` on `0` matches and `AMBIGUOUS_PATCH` on $\ge 2$ matches) and verifies `touched_symbols`.

### 2.6 Syntax Preflight, 2-Run Gate 2 Stability & Bounded Quarantine (`SyntaxPreflight` & `MockHealer`)
- `SyntaxPreflight::check_file` pipes the patched target file bytes to `node --input-type=module --check` via `run_bounded` inside the scratch sandbox before launching Chromium.
- Gate 2 executes **2 consecutive runs** (`gate2_runs_completed: 2`, `gate2_stability_passed: true`) to confirm non-flaky remediation.
- After `MAX_REPAIR_ATTEMPTS = 3` (or `180s` wall-clock timeout), the harness terminates cleanly with `TriageStatus::QuarantineRepairFailed` (`QUARANTINE_REPAIR_FAILED`, exit code `21`).

### 2.7 Integer Micro-Dollar Token Accounting (`TokenAccounting`)
- Tracks `prompt_tokens`, `cached_prompt_tokens`, `completion_tokens`, `reasoning_tokens`, `latency_ms`, and `total_cost_micros_usd` using integer nano-dollar rate cards without double-counting cached tokens (full RFC 8785 float-free canonical JSON compliance).
