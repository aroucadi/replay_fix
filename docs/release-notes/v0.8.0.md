## Executive Summary

ReplayFix v0.8.0 delivers the complete **Observability, GitHub Ingestion & Human Confirmation Gate** slice. This release transforms ReplayFix from an internal verification substrate into an inspectable, developer-friendly autonomous repair tool that integrates directly with real-world open-source workflows.

v0.8.0 introduces three flagship capabilities while upholding the substrate's constitutional invariants:
1. **Playwright Trace Viewer Auto-Launcher (`--trace`)**: Captures complete Playwright execution traces and launches the interactive visual timeline scrubber (`npx playwright show-trace`) upon run completion, with fail-safe detection that skips GUI spawn in headless CI and non-interactive environments.
2. **Live GitHub Issue Ingestion (`--issue <url>`)**: Strict HTTPS/CLI retrieval of real-world GitHub issues, extracting reproduction steps and enclosing untrusted issue descriptions in `<UNTRUSTED_ISSUE_METADATA>` security barriers.
3. **Interactive Human Confirmation Gate (`--apply` / `--yes`)**: Syntax-highlighted ANSI candidate diff preview requiring affirmative human confirmation (`[y/N]`) before applying any patch to the base working tree, with fail-closed refusal in non-interactive sessions without `--yes` (exit code 13).
4. **Disaggregated Fact Artifacts**: Atomic output of inspectable verification artifacts in `.replayfix/artifacts/` (`candidate.patch`, `approval_audit.json`, `issue_ingestion.json`, `differential_diagnosis.json`, `regression_parity.json`, `playwright.trace.zip`).

## New Capabilities & Technical Architecture

### 1. Playwright Trace Viewer Auto-Launcher (`replayfix_core::trace`)
- Records browser execution traces to `.replayfix/artifacts/playwright.trace.zip`.
- Spawns `npx playwright show-trace <path>` with detached stdio when run interactively.
- Detects non-interactive terminals (`std::io::stdout().is_terminal()`) and CI environments (`CI`, `GITHUB_ACTIONS`, `TF_BUILD`, etc.) to cleanly skip GUI auto-launch and avoid hanging automated pipelines.

### 2. Live GitHub Issue Ingestion (`replayfix_core::ingestion`)
- URL validation: Strict regular expression matching `https://github.com/{owner}/{repo}/issues/{id}`. Non-GitHub hosts, PR URLs, and path traversal strings are rejected immediately with exit code 23 (`INVALID_ISSUE_URL`).
- Secure retrieval: Uses `Platform::create_command("curl")` with 10s timeout and 512KB size cap, falling back to `gh issue view` if installed.
- Untrusted context framing: Wraps title, author, and body inside `<UNTRUSTED_ISSUE_METADATA>` blocks.
- Markdown action parser: Intelligently identifies reproduction sections and parses ordered or bulleted steps into structured task actions.
- Emits `.replayfix/artifacts/issue_ingestion.json` conforming to `contracts/issue_ingestion.schema.json`.

### 3. Interactive Human Confirmation Gate (`replayfix_cli::approval`)
- ANSI Diff Highlighter: Renders colorized unified diff previews (+green, -red, @@ cyan, headers bold).
- Displays diff metrics: files modified, additions, deletions, and candidate patch SHA-256 digest.
- Affirmative confirmation: Prompts `Apply candidate patch to base repository? [y/N]: `. Requires `y` or `yes`. Operator refusal exits with code 12 (`USER_REJECTED_PATCH`).
- Fail-closed non-interactive handling: Runs requesting base repo mutation (`--apply`) in non-TTY environments without explicit `--yes` exit with code 13 (`NON_INTERACTIVE_REFUSAL`), guaranteeing $\Delta\text{repo}=0$.
- Emits `.replayfix/artifacts/approval_audit.json` recording user decision, mode (`ManualAffirmative`, `AutoBypassFlag`, `NonInteractiveRejected`, `ManualNegative`), timestamp, and TTY status.

### 4. Worktree Patch Application (`replayfix_core::patch`)
- Added `UnifiedPatcher::apply_to_worktree(repo_dir, diff)` enabling verified and approved candidate patches to be safely applied to the base working tree with zero path traversal risk.

## Exit Codes Taxonomy Updated

| Exit Code | Identifier | Description |
|-----------|------------|-------------|
| 0 | `SUCCESS` | Harness completed verification and repair successfully |
| 1 | `DOCTOR_FAILED` | Environment doctor dependency check failed |
| 2 | `USAGE_OR_INPUT_ERROR` | Invalid CLI arguments or missing files |
| 10 | `INTERNAL_OR_SYSTEM_ERROR` | Unhandled internal or system error |
| 11 | `SECURITY_VIOLATION` | Path traversal, DOS device, or package.json test mutation |
| 12 | `USER_REJECTED_PATCH` | Interactive operator declined patch application (`[y/N]`) |
| 13 | `NON_INTERACTIVE_REFUSAL` | Base repo modification requested non-interactively without `--yes` |
| 20 | `BRIDGE_EXECUTION_FAILED` | Playwright or CDP bridge process failure |
| 21 | `QUARANTINE_REPAIR_FAILED` | Autonomous model repair failed after maximum retry budget |
| 22 | `AMBIGUOUS_GROUNDING` | Multimodal visual grounder tie (|ΔS| < 0.25) |
| 23 | `INVALID_ISSUE_URL` | Malformed, non-GitHub, or PR URL passed to `--issue` |
| 24 | `ISSUE_FETCH_FAILED` | Failed to retrieve issue (HTTP 404, rate limited, network timeout) |
| 30 | `REPAIR_REJECTED` | Candidate patch failed Gate 2 validation |
| 31 | `REGRESSION_DETECTED` | Candidate patch broke pre-existing regression test suite |
| 32 | `QUARANTINE_INVERTED_BASELINE` | Inverted defect baseline detected |
