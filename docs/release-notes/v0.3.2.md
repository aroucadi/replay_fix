## Summary

FixTream / ReplayFix **v0.3.2** elevates the CLI from a styled terminal utility to a **production-grade, trust-first interaction harness**. Incorporating the advanced interaction benchmarks of tools like Claude Code and Cargo, this release prioritizes **auditability, user control, visible security boundaries, structured diagnostics, and deterministic automation contracts**.

---

## Key Capabilities & Improvements

### 1. Three Strict Output Modes & Deterministic Precedence
- **Output Modes**:
  - `Human` (default): Polished semantic layout, banners, step indicators, and audit summaries.
  - `Quiet` (`--quiet` / `-q`): Suppresses all decorative and informational output, emitting strictly machine outcomes and errors.
  - `Machine` (`--json`): Pure, unpolluted JSON data emitted cleanly to stdout.
- **Deterministic Color Precedence**:
  1. Explicit CLI argument (`--color <auto|always|never>`) wins unconditionally.
  2. `NO_COLOR` environment variable (disables color when set).
  3. `CLICOLOR_FORCE` (forces color when set to a non-zero value).
  4. `TERM=dumb` (disables color and ANSI formatting).
  5. Stream TTY detection via standard library `std::io::IsTerminal` independently evaluated for stdout and stderr.

### 2. User-Visible Security & Trust Boundaries
- Before running mutations or tests, FixTream prints an explicit **Security & Isolation Guarantee Card**:
  - Declares target repository mutation policy (`Strictly Read-Only (Δrepo = 0 invariant enforced)`).
  - Reports ephemeral scratch sandbox state (`Active in OS temp dir`).
  - Confirms SHA-256 test freeze invariant.

### 3. Actionable Diagnostic Engine (`replayfix doctor`)
- Overhauled from a simple status table to a full diagnostic inspection suite:
  - **Status**: `[OK]`, `[WARN]`, `[MISSING]`, `[NOT CHECKED]`.
  - **Finding**: Clear statement of detected state.
  - **Evidence**: Concrete version numbers and paths.
  - **Impact**: Explicit risk explanation if the prerequisite is unmet.
  - **Action**: Concrete copy-pasteable remediation command.

### 4. Dry-Run & Non-Destructive Preview (`--dry-run`)
- `replayfix repro --dry-run` validates all arguments, manifests, candidate patches, and repository isolation parameters without executing gates or applying patches.

### 5. Deterministic Operational Steps & Audit Summary
- Operational phases are marked with explicit status labels (`[RUN]`, `[PASS]`, `[FAIL]`, `[SKIP]`) rather than mere colored icons.
- Completion outputs an executive audit card with clear next steps.
