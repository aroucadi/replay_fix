# ReplayFix v0.2.1 — Clean Architecture & SSOT Refactoring

**Released:** 2026-10-27 · **Maintenance Release for:** `v0.2.0`

v0.2.1 is a surgical maintenance release that hardens single-source-of-truth (SSOT) boundaries, eliminates redundant string serialization overhead, and centralizes CLI process exit codes following the comprehensive post-v0.2 engineering audit.

## Summary of Changes

- **SSOT `TriageStatus` Display**: Added native `as_str()` and `std::fmt::Display` implementation for `TriageStatus` in `replayfix_core::receipt`, eliminating the indirect `serde_json::to_value` string extraction in the CLI.
- **SSOT Process Exit Codes**: Defined `replayfix_cli::exit_codes` (`SUCCESS = 0`, `DOCTOR_FAILED = 1`, `USAGE_OR_INPUT_ERROR = 2`, `INTERNAL_OR_SYSTEM_ERROR = 10`, `SECURITY_VIOLATION = 11`, `REPAIR_REJECTED = 30`), eliminating scattered magic numbers across CLI execution pathways.
- **Root Crate Exports**: Re-exported `TriageStatus`, `AUDIT_RECEIPT_FILE`, and `TRIAGE_REPORT_FILE` directly from the `replayfix_core` crate root for a cohesive library API.
- **Automated Verification**: Added unit tests verifying `as_str()` values and proving strict parity between `TriageStatus.as_str()` and serde JSON serialization.
- **Zero Architectural Inconsistencies**: All 83 automated workspace tests (68 core + 15 CLI integration) pass with 100% compliance, zero compiler warnings, and zero clippy lints.

## Upgrading from v0.2.0

Fully backwards compatible drop-in replacement. No configuration or command-line invocation changes are required.
