## Executive Summary

ReplayFix v1.7.0 transforms ReplayFix from an interactive local CLI utility into an **autonomous, continuous GitHub triage bot**.

Software engineering teams receive dozens of bug reports with screen recordings that sit unaddressed for days. ReplayFix v1.7.0 closes the gap between human issue reporting and verified production pull requests. By connecting directly to GitHub issues and webhook streams, ReplayFix autonomously ingests bug videos (`.mp4`, `.webm`, `.mov`), extracts problem narratives, isolates repairs inside ephemeral scratch sandboxes ($\Delta\text{repo}=0$), synthesizes permanent Playwright regression specs (`tests/repro/rf_issue_<id>.spec.ts`), commits fixes with Ed25519-signed Merkle commit trailers, opens verified Pull Requests with comprehensive Evidence Matrices, and posts cryptographic verification proof directly back to the issue thread while updating triage labels (`replayfix:verified-healed`, `replayfix:unreproduced`, `replayfix:ambiguous`).

The triage bot operates in both **on-demand CLI mode** (`replayfix bot --issue <url>`) and **continuous HTTP webhook listener mode** (`replayfix bot --listen 0.0.0.0:8080 --webhook-secret <secret>`), fully equipped with RFC 2104 constant-time HMAC-SHA256 signature verification (`X-Hub-Signature-256`) and robust anti-loop bot filtration (`BOT_LOOP_MARKER`).

## The 5 Pillars of Release 1.7

### Pillar 1: Multimodal GitHub Issue Ingestion & Media Quarantine
- **Markdown & HTML Video Extraction**: High-precision parser extracting video attachments across GitHub user-attachment formats (`https://github.com/user-attachments/assets/...`, `https://github.com/.../assets/...`), Markdown video/link syntax (`[recording.mp4](url)`, `![video](url)`), and HTML `<video src="...">` tags.
- **Container Validation**: Preflights media stream magic headers (`ftyp` for MP4/MOV, `\x1a\x45\xdf\xa3` for WebM) before decoding, rejecting corrupt or malicious payloads.
- **Media Scratch Quarantine**: Downloads videos into isolated scratch directories (`.replayfix/bot/issues/<id>/video.<ext>`) with strict path traversal guards (`TaskManifest::assert_safe_path`).

### Pillar 2: Constant-Time HMAC-SHA256 Webhook Server & Anti-Loop Immunity
- **RFC 2104 Webhook Verification**: High-throughput async HTTP webhook receiver validating incoming `X-Hub-Signature-256` headers using HMAC-SHA256 with constant-time equality comparisons (`subtle::constant_time_eq`), rejecting invalid payloads with HTTP 401 Unauthorized.
- **Anti-Loop Bot Guard**: Neutralizes infinite event recursion by detecting `[bot]` usernames, `sender.type == "Bot"`, or the presence of the ReplayFix cryptographic triage comment marker (`<!-- replayfix-triage-marker -->`), acknowledging and discarding non-actionable events with HTTP 202 Accepted.
- **Async Execution Buffer**: Offloads intensive triage operations to background Tokio tasks while immediately returning HTTP 200 OK to GitHub within the 10-second webhook timeout SLA.

### Pillar 3: Ephemeral Scratch Isolation & Sovereign Healer Pipeline ($\Delta\text{repo}=0$)
- **Zero Base Repo Contamination**: Clones the target repository into an ephemeral scratch worktree with dual-layer immutability checks (`WorktreeManifest`), guaranteeing $\Delta\text{repo}=0$ on the host workspace.
- **Full Sovereign Healer Execution**: Re-uses the complete sub-60s v1.6 pipeline (SAM 3.1 + Muse Voice + Muse Spark Agent Loop + Muse Wonder AST Search/Replace Repair + Gate 2 Stability Quorum + Gate 3 Stress Quorum + Permanent Inoculation).
- **Hermetic Mock & Deterministic Modes**: Supports `--mock-heal` for hermetic, offline CI qualification, with pre-seeded test fixtures and mock GitHub transports.

### Pillar 4: Autonomous Pull Request Dispatch & Issue-Numbered Inoculation
- **Permanent Issue-Specific Regression Specs**: Generates permanent Playwright end-to-end regression specs named specifically for the issue: `tests/repro/rf_issue_<id>.spec.ts`.
- **Branch Naming Standard**: Creates isolated branches following the deterministic pattern `replayfix/issue-<id>-<slug>` (e.g. `replayfix/issue-42-cart-quantity-overflow`).
- **Cryptographic Commit Trailers**: Commits code patches and regression specs with conventional commit headers (`Fixes #<id>`) and RFC 6962 / Ed25519 Merkle commit trailers, including `ReplayFix-Issue: <url>`.
- **Automated PR Dispatch**: Dispatches pull requests via GitHub API / `gh` CLI containing the full markdown Evidence Matrix, reproduction contract digests, and test logs.

### Pillar 5: Issue Thread Evidence Commenter & Automated Triage Labels
- **Cryptographic Proof Comments**: Automatically comments on the original issue with verified proof:
  - Gate 1 RED vs Gate 2 GREEN behavioral contracts
  - Side-by-side DOM `ariaSnapshot` diffs showing pre-repair and post-repair states
  - Video keyframe and optical flow ROI references
  - RFC 6962 Merkle Tree receipt root and Ed25519 cryptographic signature digest
- **Automated Triage Labeling**:
  - `replayfix:verified-healed`: Assigned when Gate 1 is RED, Gate 2 is GREEN (2x stability), Gate 3 stress quorum passes, and PR is dispatched.
  - `replayfix:unreproduced`: Assigned when the reported behavior cannot be reproduced on Gate 1.
  - `replayfix:ambiguous`: Assigned when visual grounding margin is insufficient (`margin < 0.25`).
- **Failure Diagnostics**: Posts structured failure diagnostic comments when bugs cannot be reproduced or repaired within bounded budgets.
