## 1. Executive Summary

Release `v0.6.2` is a surgical patch release addressing packaging integrity, Windows test runner resiliency, NTFS directory junction exclusion during workspace sandbox seeding, and lexical scope parsing hygiene discovered during clean-room and adversarial auditing.

## 2. Hardening Deliverables & Root-Cause Fixes

### 2.1 Git Packaging & Panic Verification Reproducibility ([F-02])
- **Root Cause**: `.gitignore` globally ignored `.specify/`, preventing `.specify/scripts/check-panics.ps1` from being tracked in Git despite running locally.
- **Fix**:
  - Updated `.gitignore` to allow `.specify/scripts/` and its contents (`!.specify/scripts/`).
  - Added a first-class script at `scripts/check-panics.ps1` to support standard CI workflows without `.specify/` tooling dependencies.
  - Dynamically detects the workspace root by walking parent directories looking for `Cargo.toml`, ensuring the scanner runs reliably regardless of invocation working directory.

### 2.2 Windows Test Runner Exit Code Resiliency ([F-01])
- **Root Cause**: In `crates/replayfix-cli/tests/cli.rs`, `fn code(out: &Output) -> i32` called `out.status.code().expect("process was terminated by a signal")`. On Windows, abnormal process exits or signals can cause `code()` to return `None`, causing the test runner itself to panic with exit code 101.
- **Fix**:
  - Replaced `.expect(...)` with `out.status.code().unwrap_or(-1)`. Standard assertion checks now handle the resulting exit code without runner aborts.

### 2.3 NTFS Directory Junction Exclusion in Sandbox Seeding ([F-06])
- **Root Cause**: In `crates/replayfix-core/src/worktree.rs`, `collect_entries` and `copy_tree` only checked `file_type.is_symlink()`. On Windows, NTFS directory junctions (`mklink /J`) report `file_type.is_dir() == true` and `file_type.is_symlink() == false`, allowing junction targets to be traversed during initial sandbox cloning.
- **Fix**:
  - In both `collect_entries` and `copy_tree`, inspected `fs::symlink_metadata` and evaluated `is_symlink_or_reparse_point(&symlink_meta)`. Any directory junction or reparse point is now skipped during workspace fingerprinting and cloning.

### 2.4 Comment & String Literal Stripping in `BlockPatcher` ([F-04])
- **Root Cause**: `BlockPatcher::open_enclosing_declarations` scanned raw bytes for declaration keywords and braces. Declarations commented out (e.g., `// function fake() {`) or inside string literals could introduce spurious scope stack frames.
- **Fix**:
  - Implemented `strip_comments_and_strings` in `BlockPatcher` that blanks out single-line comments (`//`), block comments (`/* */`), and string literals (`"..."`, `'...'`, `` `...` ``) with spaces prior to brace and token parsing.
  - Added unit test asserting that commented declarations and in-string declaration keywords are excluded from `touched_symbols` validation.
