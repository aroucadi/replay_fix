# ADR-07: Reproducible Release Packaging & Public Hosting Hygiene

## Status
Accepted

## Context
`proof_viewer.html` is designed to be opened directly from a local checkout (`file://`) or hosted as a static artifact (e.g., GitHub Pages / Devpost review), and must include representative, sanitized example receipts (`RF-01` single audit receipt, `RF-01..RF-05` sweep receipt, and a tampered adversarial receipt) so judges can test all verification states immediately or drop their own files.

## Decision
1. **Sanitized Embedded Demo Presets + Drag-and-Drop File Importer**:
   - `proof_viewer.html` ships with three clearly labeled, cryptographically real presets generated from the deterministic Rust engine (1: Verified Genuine `RF-01` Audit Receipt + Merkle Proof, 2: Verified 5-Bug Sweep Receipt `RF-01..RF-05`, 3: Tampered Leaf / Broken Proof Adversarial Demo) **in addition to** full drag-and-drop and file-picker import for arbitrary `audit_receipt.json`, `merkle_receipt.json`, and `sweep_receipt.json` files from disk.
2. **Zero Secrets in Public Artifacts**:
   - Only public Ed25519 verifying keys (`32-byte` hex) are embedded in the portal's default pinned trust store; private signing keys and API tokens are strictly excluded and verified absent via automated tests.

## Consequences
- **Positive**: Judges can both evaluate real cryptographic verification in one click and drop arbitrary receipts generated by `replayfix` from their own terminal runs.
